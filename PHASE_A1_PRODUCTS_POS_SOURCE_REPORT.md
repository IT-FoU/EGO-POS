# Phase A.1 - Products + POS Real Source Integration Report

Date: 2026-06-21

Status: Code/build completed. Manual UI verification required before PASS.

## Scope

Implemented only:

- Products source integration
- POS product source integration
- Product/POS repository sync
- Product/cart key stability

Not touched:

- Reports
- Inventory
- Purchasing
- Permissions beyond existing POS guards

## 1. Product Create Result

Product create now writes through:

- `demoProductsRepository.addProduct`

Changed file:

- `features/products/components/product-form.tsx`

Result:

- Create Product no longer writes directly to `localStorage`.
- New products are saved into the stable central key `ego.pos.products`.
- Product IDs are generated by the central repository helper.
- POS reads the same repository source.

Manual verification required:

1. Open `/products/new`.
2. Create a product with name, barcode, SKU, price, and opening stock.
3. Save.
4. Confirm it appears on `/products`.
5. Open `/pos`.
6. Confirm it appears in the POS product grid.

## 2. Product Edit Result

Product edit now loads local demo products through:

- `ProductEditClient`
- `demoProductsRepository.findProduct`

Changed files:

- `app/(dashboard)/products/[productId]/edit/page.tsx`
- `features/products/components/product-edit-client.tsx`
- `features/products/components/product-form.tsx`

Result:

- Product edit route no longer relies on server mock `getProductById`.
- Locally created demo products can be opened for edit.
- Saving edits uses `demoProductsRepository.updateProduct`.
- Edited values written back include:
  - Name
  - Barcode
  - SKU
  - Product code
  - Cost price
  - Selling price
  - Stock
  - Category
  - Unit fields
  - Image fields

Manual verification required:

1. Create a product.
2. Click Edit from `/products`.
3. Change name, price, barcode, SKU, and stock.
4. Save.
5. Confirm the product list updates.
6. Open `/pos`.
7. Confirm POS shows the edited name, price, stock, barcode, and SKU.

## 3. Product Delete Result

Product delete now uses:

- `demoProductsRepository.deleteProduct`
- `demoProductsRepository.deleteProducts`
- `demoProductsRepository.clearProducts`

Changed files:

- `features/products/components/product-list-client.tsx`
- `features/products/components/product-form.tsx`

Result:

- Single delete from product list uses central repository.
- Bulk delete uses central repository.
- Clear products uses central repository.
- Delete from edit page uses central repository.
- Deleted products are removed from `ego.pos.products`.

Manual verification required:

1. Create a product.
2. Confirm it appears in POS.
3. Delete it from Products.
4. Return to POS.
5. Confirm it disappears from POS.

## 4. POS Product Sync Result

POS now loads products from:

- `demoProductsRepository.listProducts`

Changed file:

- `features/pos/components/pos-page-client.tsx`

Result:

- POS no longer reads product data from a hardcoded localStorage key.
- POS no longer uses POS mock products for demo product grid.
- POS filters out inactive/deleted products from the sellable grid.
- POS reloads demo products on:
  - initial load
  - browser storage event
  - window focus

Manual verification required:

1. Create product in Products.
2. Open POS and confirm product appears.
3. Edit product in Products.
4. Return/focus POS and confirm updated values appear.
5. Delete product in Products.
6. Return/focus POS and confirm product disappears.

## 5. Pay Duplicate-Key Crash Result

Changes:

- Added optional `cartLineId` to `PosCartItem`.
- New cart items receive `cartLineId = productId:unitId`.
- Cart and receipt renderers use `cartLineId` when available.
- Same product/unit additions merge quantity into the existing line.
- Product grid keys still include product id, unit id, and index for legacy duplicate safety.

Changed files:

- `features/pos/types.ts`
- `features/pos/components/pos-page-client.tsx`

Expected result:

- Clicking Pay should not crash from duplicate React keys.
- Legacy duplicate product IDs are normalized by the Phase A.0 product repository.

Manual verification required:

1. Create a product.
2. Open POS.
3. Add the same product multiple times.
4. Confirm quantity increases in one cart row.
5. Click Pay.
6. Confirm no duplicate key crash appears.
